# Участие в проекте

Спасибо за интерес! Проект учебно-практический, но развивается как продуктовый: изменения принимаются через pull request
с тестами и обновлённой документацией. Подробные правила для разработки — в [AGENTS.md](AGENTS.md).

## Быстрый старт разработчика

```bash
git clone https://github.com/RainCherb/ai-adoption-compass && cd ai-adoption-compass
make install          # Python 3.11+
make web              # Node 24.15+
make check            # должно быть зелёным до начала работы
```

## Как предложить изменение

1. Создайте ветку от `main`: `feature/<кратко>` или `fix/<кратко>`.
2. Напишите тест, который падает без вашего изменения.
3. Реализуйте изменение; `make format && make check`.
4. Если менялся API — `make openapi`; если менялись формулы — обновите `docs/METHODOLOGY.md`.
5. Откройте pull request по шаблону: что и зачем, как проверено.

Коммиты — в повелительном наклонении, по одной мысли: `Добавить детектор номера ОГРН`, `Исправить округление окупаемости`.

## Обновление зависимостей

Dependabot объединяет minor/patch-обновления Python и фронтенда в отдельные группы; GitHub Actions обновляются одной
группой ежемесячно. Обновления проверяются полным CI перед слиянием.

Major-обновления TypeScript и `@types/node` отложены: `openapi-typescript` 7 требует TypeScript 5, а типы Node должны
соответствовать ветке 24, используемой в CI и Docker. При смене этих ограничений обновите `.github/dependabot.yml`.

Ветка `main` защищена: изменения проходят через PR с актуальной базой, успешными проверками бэкенда (Python 3.11/3.12),
фронтенда и Docker и разрешёнными обсуждениями. Эти правила действуют и для администраторов; force push и удаление ветки
запрещены. Поддерживается линейная история — используйте squash или rebase. Обязательное одобрение второго участника
не требуется, чтобы автор мог самостоятельно сопровождать репозиторий.

## Данные каталога моделей

Цены и оценки быстро устаревают. При обновлении записи в `catalog.yaml`:

* сверьтесь с официальной страницей провайдера (ссылка в поле `pricing_url`) и обновите `reviewed_at`;
* оценки качества (1–5) подтверждайте замерами `compass eval` на данных, близких к реальным;
* не копируйте материалы, права на которые вам не принадлежат.

## Безопасность

Не добавляйте в репозиторий реальные персональные данные, ключи и токены — ни в код, ни в тесты, ни в документацию.
О найденных уязвимостях сообщайте по [SECURITY.md](SECURITY.md), а не через публичные issue.
