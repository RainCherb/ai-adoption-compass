# Политика безопасности

## Поддерживаемые версии

Исправления безопасности выпускаются для последней минорной версии (сейчас — 1.0.x).

## Как сообщить об уязвимости

Используйте приватное сообщение об уязвимости на GitHub: **Security → Report a vulnerability** в этом репозитории.
Пожалуйста, не создавайте публичные issue для уязвимостей и не прикладывайте реальные персональные данные или ключи.
Опишите, что и как воспроизводится, затронутые версии и возможное влияние.

## Область

В области: обход ограничений пути в MCP-инструментах и раздаче фронтенда, утечка исходных текстов в журнал или ответы API,
инъекции через шаблоны, ложные «разрешено» в проверке данных, уязвимости зависимостей.

## Важные допущения

* Приложение **не содержит аутентификации** и рассчитано на локальный запуск или внутренний контур.
  Не публикуйте порт в интернет без reverse proxy с авторизацией. Docker Compose из репозитория публикует порт только на `127.0.0.1`.
* Детекторы персональных данных — правила и эвристики, а не гарантия: они снижают риск, но не заменяют процессы
  информационной безопасности и юридическую оценку.
* Встроенный каталог моделей и политика — демонстрационные шаблоны; перед использованием в компании адаптируйте их
  и согласуйте с ИБ и юристом.
* Файлы соответствий для обратимого обезличивания содержат исходные данные. В Linux/macOS им назначаются права `0600`;
  в Windows `chmod` не ограничивает ACL — храните такие файлы в папке с доступом только для вашей учётной записи.
