# Публичное интерактивное демо

Адрес: **[ai-adoption-compass-demo.onrender.com](https://ai-adoption-compass-demo.onrender.com)**.
Сервис `ai-adoption-compass-demo`, Render Free, Frankfurt; опубликованная ветка — `main`.

Демо разворачивается как один Docker web service на бесплатном плане Render. Браузеру посетителя не нужны Python,
Node.js, аккаунт или API-ключ. В подбор, экономику и отчёты встроены Sonnet 5.5, GPT-6.1 Sol и DeepSeek V4.1 Flash. В «Оценке процессов» открыты 18 синтетических процессов; можно менять допущения ROI,
изучать карточки процессов, подбирать модели, проверять вымышленные тексты, рендерить промпты и сравнивать измерения LLM.

## Развёртывание

В репозитории есть `render.yaml` для Render Blueprint. Параметры web service:

| Параметр | Значение |
| --- | --- |
| Repository | `https://github.com/RainCherb/ai-adoption-compass` |
| Branch | `main` |
| Runtime / Plan | Docker / Free |
| Dockerfile | `./Dockerfile` |
| Environment | `COMPASS_DEMO_MODE=1` |
| Docker command | Оставить пустым: контейнерный launcher выбирает demo mode и читает `PORT` без shell |
| Health check | `/api/health` |

Перед направлением трафика убедитесь, что `/api/health` возвращает `demo_mode: true` и версию `1.4.0`.
Если параметр отсутствует или равен `false`, сервис нельзя использовать как общедоступное демо.

Текущий сервис создан из публичного URL репозитория, без подключения GitHub к Render. Поэтому после зелёного CI
нужен **Manual Deploy → Deploy latest commit** в панели сервиса или эквивалентный вызов Render API.
Само поле `autoDeploy=yes` в API не подтверждает наличие Git-интеграции: для публичных Git URL автоматические
деплои [не поддерживаются](https://render.com/docs/deploys#automatic-deploys). Перед повторным запуском проверьте
историю деплоев, чтобы не создавать дубликат уже выполняющейся сборки.

Для будущих автоматических обновлений владелец может подключить GitHub в Render, связать этот же сервис
с репозиторием и выбрать **After CI Checks Pass**. Создавать второй сервис для этого не требуется.

Бесплатный Render засыпает после 15 минут простоя; первое открытие может занять около минуты.
Это ограничение [плана Render Free](https://render.com/docs/free), а не ошибка приложения. Для демо не нужны
постоянный диск, БД или платный inference.

## Запросы каждые 10 минут

Workflow [Demo keep-alive](https://github.com/RainCherb/ai-adoption-compass/actions/workflows/demo-keep-alive.yml)
из `.github/workflows/demo-keep-alive.yml` запрашивает `/api/health` каждые 10 минут:
на 7-й, 17-й, 27-й, 37-й, 47-й и 57-й минуте каждого часа. Он работает в GitHub независимо от компьютера владельца,
только в исходном репозитории и ветке `main`. Также доступен ручной **Run workflow**.

Проверка не требует токенов, checkout, установки зависимостей или API-ключей. Выполняется один HTTPS GET
с ограниченным повтором при сетевой ошибке/холодном старте. Успех означает корректный JSON, `status=ok`
и `demo_mode=true`; ошибки остаются видны в Actions. Расчёты, оценки и LLM не запускаются.

Это помогает сохранять демо активным, но не даёт гарантии отсутствия спячки: GitHub может задержать или пропустить
запуск, а в публичном репозитории отключает расписания после 60 дней без активности. Для восстановления откройте
workflow в Actions и нажмите **Enable workflow**. Чтобы остановить запросы, выберите **Disable workflow**.
Не создавайте фиктивные коммиты ради продления расписания.

Постоянно работающий сервис расходует общие 750 бесплатных instance-hours Render в месяц (24 часа × 31 день = 744).
Если в workspace есть другие бесплатные web services, часы суммируются; при исчерпании лимита Render приостановит
сервисы до следующего месяца. Keep-alive не отменяет эти ограничения и перезапуски платформы.

Официальные условия: [GitHub schedule](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule),
[Render Free](https://render.com/docs/free).

## Изоляция и пределы

* В демо не создаётся SQLite. Единственная оценка `demo` строится в памяти из встроенного синтетического CSV.
* Ввод в расчёты, проверку текста и промпты обрабатывается сервером, но не сохраняется приложением и не отправляется LLM.
  Внешний хостинг может вести собственные инфраструктурные журналы; реальные ПДн и секреты в демо вводить нельзя.
* Загрузка CSV, создание и удаление оценок возвращают `403`. Журнал `/api/audit` пуст для всех посетителей.
* Пересчёт `/api/assess` работает без сохранения: до 50 процессов и 128 КБ тела запроса. Сценарий «что-если» остаётся
  в памяти вкладки; скачиваемые отчёты относятся к исходной оценке, что явно указано в интерфейсе.
* Общий лимит — 180 API-запросов в минуту на процесс, без хранения IP. Health/meta доступны при исчерпанном лимите;
  прочие запросы получают `429` с `Retry-After: 60`. Предел параллельности процесса — 32.
* Запросы к сетевым провайдерам, серверы LLM и обновление источников из публичного API недоступны. Интерфейс читает
  только опубликованные измерения и снимки. API-ключи в сервис не загружаются.

Обычный режим приложения без `COMPASS_DEMO_MODE` сохраняет SQLite и загрузку CSV; модели при этом также предлагаются только по API.
При сохранённом Docker ENTRYPOINT demo mode запускает ограниченный API независимо от CMD. Вне demo mode launcher
выполняет CMD без изменений. Поле **Docker Command в Render должно быть пустым**: его переопределение может заменить
также ENTRYPOINT и обойти launcher. Не задавайте здесь shell-команду с вложенными кавычками. После изменения
настройки дождитесь нового деплоя и выполните HTTP smoke: одна лишь успешная сборка не подтверждает запуск приложения.

## Приёмка

Автотесты: `tests/test_public_demo.py`, `tests/test_measured_benchmark.py`, `tests/test_catalog_sources.py`,
`web/src/pages/assessment/PublicDemo.test.tsx`, `web/src/pages/evals/MeasuredEvals.test.tsx`.

После публикации проверить health и флаг режима, открытие готовой оценки, пересчёт сценария, подбор моделей,
обезличивание, промпты, вкладку измерений, актуальность источников, пустой журнал, запрет записи и защитные HTTP-заголовки.

Для повторяемой HTTP-проверки без сторонних зависимостей:

```bash
python scripts/smoke_demo.py --base-url https://ai-adoption-compass-demo.onrender.com
```

Тот же скрипт в CI проверяет отдельный Docker-контейнер именно в публичном режиме, включая запрет записи и граничное число.

Тарифный экран: [источники и метод расчёта](FEATURED_MODELS.md). Порядок карточек не является рейтингом качества.

Сравнение стоимости и накопленного эффекта, единицы графиков и доступность API из России: [подробный разбор](API_COST_ANALYTICS.md). Локальные измерения находятся в архиве документации и не отображаются в интерфейсе.
