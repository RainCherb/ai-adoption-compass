# Веб-интерфейс AI Adoption Compass

Одностраничное приложение на **React 19 + TypeScript (strict) + Vite**. Работает поверх REST API бэкенда
(`/api/*`, контракт — [`../docs/openapi.json`](../docs/openapi.json)) и после сборки раздаётся самим FastAPI:
отдельный веб-сервер и внешние сервисы не нужны.

Шесть разделов: оценка процессов и ROI, подбор моделей, безопасность данных, промпты, качество моделей, журнал.

## Быстрый старт

Нужны Node.js 22.22.2+, 24.15+ или 26+ и npm; рекомендуем ветку 24 LTS.

```bash
npm ci            # установить зависимости строго по package-lock.json
npm run dev       # dev-сервер на http://localhost:5173, запросы /api уходят на 127.0.0.1:8000
```

API для разработки запускается из корня репозитория:

```bash
COMPASS_DB=/tmp/compass.db compass serve --port 8000
```

Сборка для продакшена кладёт файлы прямо в пакет бэкенда (`../src/adoption_compass/static`):

```bash
npm run build     # tsc -b && vite build
compass serve     # из корня репозитория: интерфейс на http://127.0.0.1:8000
```

Из корня то же самое делает `make web`.

## Команды

| Команда                 | Что делает                                                                 |
| ----------------------- | -------------------------------------------------------------------------- |
| `npm run dev`           | dev-сервер Vite с проксированием `/api`                                    |
| `npm run build`         | проверка типов и продакшен-сборка в `../src/adoption_compass/static`       |
| `npm run preview`       | локальный просмотр собранного приложения (тоже проксирует `/api`)          |
| `npm run typecheck`     | `tsc -b`: строгая проверка типов, включая тесты                            |
| `npm run lint`          | ESLint (flat config, typescript-eslint, react-hooks), предупреждения = 0   |
| `npm test`              | Vitest: unit- и компонентные тесты в jsdom                                 |
| `npm run test:coverage` | то же с отчётом о покрытии (v8)                                            |
| `npm run gen:api`       | перегенерировать `src/api/schema.d.ts` из `../docs/openapi.json`           |

После изменения API: `make openapi` в корне (обновит `docs/openapi.json` и вызовет `npm run gen:api`), затем
`npm run typecheck` — компилятор покажет, где фронтенд разошёлся с контрактом.

## Как устроено

```
src/
  api/          типизированный клиент (client.ts), нормализация ошибок (errors.ts),
                сгенерированные типы (schema.d.ts) и удобные алиасы (types.ts)
  lib/          форматтеры ru-RU (format.ts), хеш-маршруты, подсветка находок, подписи
  hooks/        useAsync, useAction, useDebounced, useTheme, useHashRoute, useMeta
  components/   ui/ — кнопки, баннеры, вкладки, панель; charts/ — графики на SVG; layout/ — каркас
  pages/        assessment, advisor, safety, prompts, evals, audit — по папке на раздел
  styles/       tokens.css (дизайн-токены), base.css, layout.css, components.css, pages.css
  test/         setup, подмена fetch, типизированные фикстуры
```

Ключевые решения:

- **Приватность — свойство продукта.** Сервер отдаёт строгий CSP (`script-src 'self'`, `connect-src 'self'`), поэтому
  в приложении нет inline-скриптов, `eval`, CDN, веб-шрифтов и аналитики. Тема выставляется до первой отрисовки внешним
  файлом `public/theme-init.js`. Все обращения — только к `/api/*` на том же origin.
- **Контракт API — единственный источник типов.** Клиент использует типы, сгенерированные `openapi-typescript`.
  Подписи перечислений (типы задач, категории данных, квадранты, действия) берутся из `/api/meta`, а не дублируются.
- **Одна форма ошибки.** Клиент приводит три формата ответов бэкенда (`detail` строкой, `{message, errors}` и список
  валидации FastAPI) к `ApiError` с читаемым русским текстом; сбой сети и не-JSON ответ обрабатываются отдельно.
- **Графики без библиотек.** Матрица приоритетов, кольца оценок, тепловая карта ошибок — собственный SVG/CSS с
  `<title>`/`<desc>`, доступной клавиатурой и текстовым дублированием цвета.
- **Смещения находок — кодовые точки Unicode.** Бэкенд отдаёт индексы строки Python, поэтому `lib/findings.ts`
  разбирает текст через `Array.from` (эмодзи не сдвигают подсветку).
- **Маршрутизация по хешу** без роутера: `#/assessment` (по умолчанию), `#/advisor`, `#/safety`, `#/prompts`,
  `#/evals`, `#/audit`.
- **Тема:** тёмная или светлая по `prefers-color-scheme`; переключатель в шапке сохраняет выбор в
  `localStorage` (`compass-theme`). Цвета заданы парами `light-dark()` в `tokens.css`, контраст текста — не ниже AA.
- **Доступность:** семантические ориентиры, подписи ко всем полям, фокус-кольца, управление с клавиатуры (в том числе
  пузырьками диаграммы и боковой панелью), `prefers-reduced-motion`; цвет всегда дополнен значком или текстом.

## Тесты

Vitest + Testing Library + jsdom; сеть не используется: `fetch` подменяется в `src/test/mockFetch.ts`, а необработанный
запрос роняет тест. Фикстуры в `src/test/fixtures.ts` типизированы схемой API. Тесты идут в часовом поясе UTC
(`vite.config.ts`), поэтому даты не зависят от машины.

Покрыто: форматтеры, клиент и три формата ошибок, подсветка с эмодзи, диаграммы и кольца, панель и вкладки, хеш-маршруты,
тема, а также сценарии всех страниц (загрузка демо и CSV, «что-если», подбор моделей, проверка текста и возврат значений,
шаблоны и линтер промптов, сравнение моделей, журнал).
